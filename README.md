# Agent + JEV Harness

**给你的 AI 助手一套可检查的工作流程。**

如果你已经让 AI 做日报、查资料、整理客户需求或制作方案，你可能也有这样的困惑：

“它看起来什么都懂，为什么最后还是要我一项项检查？”

这个项目想和你一起解决这个问题：把任务里的关键判断、检查要求和完成依据讲清楚，再通过 JEV 和程序把其中一部分接进 AI 的工作流程。

本项目回答三个问题：**为什么需要？它是什么、为什么这样设计？企业的经营者（创业者、老板）怎么用？**

这是一个可运行的早期项目。当前提供开工分流、交付证据摘要复核与合成演示；企业实际效果仍待验证。

仓库直接提供实现这些能力的 Python 源码、MCP / 命令行入口、依赖清单和测试。经营者可以先读说明，再把同一个仓库交给自己的 Agent 或技术伙伴检查并协助接入。

## 1. 为什么需要？从一句“已经完成”说起

假设你让 AI：

> 帮我整理昨天的经营日报，核对数据，并发送到指定工作群。

它回复“完成了”。你最关心的几个问题，却可能还没有答案：

- 用的是昨天的完整数据吗？
- 表里的数字核对过吗？
- 日报只是生成了，还是已经发送？
- 工作群里实际能看到吗？

这说明，给 AI 一个目标之外，还需要一套可检查的工作流程：哪些事实必须核对，什么情况需要补查，用什么证据证明完成。

Harness 就是承载这些要求的机制。JEV 则可以在其中回答一些范围清楚的小问题，例如“这项完成声明是否被提供的证据支持”。

**我们希望减少的是任务中的遗漏和返工。** 是否有效，要看接入前后的实际结果。

并非所有工作都要增加 JEV：写文案、自由讨论未必需要；金额加总、日期计算、订单精确匹配应优先由普通程序完成。

## 2. JEV Harness 是什么？为什么这样设计？

先记住三个部分：

| 部分 | 用经营者熟悉的话理解 | 实际负责什么 |
|---|---|---|
| Agent | 你的 AI 助手 | 理解任务、查资料、使用工具、制作结果 |
| JEV | 回答小问题的判断员 | 在给定信息和明确选项内给出判断与概率信号 |
| Harness | 一套工作规范和检查机制 | 规定何时判断、怎样检查、出了问题怎么办 |

**Agent + JEV Harness，就是让 AI 助手在既定流程中使用 JEV 的判断能力，并由程序检查和处理结果。** 经营者仍负责业务目标、授权范围和验收标准。

### 为什么让 JEV 参与？

写一份方案，需要组织语言和综合理解；判断一条证据是否支持某项声明，可能只需要在“支持、不支持、矛盾”中选择。

JEV 提供适合后者的类型化判断接口，返回明确的结果和概率信号，便于程序处理。接口形态可查阅 [TypeSafe 官方说明](https://docs.typesafe.ai/concepts/system-one)。

我们因此尝试把它用于一些小判断。但“多一个模型”不自然等于“更准确”：JEV 也会出错，需要与规则检查、原有 AI 的结构化输出一起比较，验证有没有额外价值。

### Harness 为什么不能只是一段提示词？

“认真检查，不要犯错”表达了愿望。具体流程还需要处理：

- 没有证据，不能当成检查通过。
- 返回格式不合要求，不能直接交给后续程序。
- 判断不明确，需要继续核实。
- 服务超时，必须说明本次没有完成 JEV 检查。
- 任何判断结果，都不能替代发消息、付款或发布的原有授权。

本项目同时提供 Agent 指引和程序检查。指引帮助 Agent 选择何时调用；程序负责它能确定检查的部分。当前仍可能漏调用，尚未强制拦截全部工具操作。

### 第一版怎样帮助 AI 执行任务？

```text
你交代任务
    ↓
开工前：JEV 建议处理路线、提示可能缺少的条件
    ↓
Agent 执行工作，读取原始资料和工具结果
    ↓
交付前：JEV 对照“完成声明”和“证据摘要”
    ↓
Agent 核对疑点、补做工作，或明确说明未完成部分
    ↓
你查看结果和依据
```

JEV 看的是提供给它的摘要，不会亲自打开你的业务系统。摘要错了、漏了，它也可能判断错。因此实际计算、事实查询和结果验证仍需由程序、Agent 或人完成。

## 3. 企业的经营者怎么用？

先选一件你想交给 AI、却还需要反复盯的工作。你可以先了解方法与案例，安装由能够使用工具的 Agent 或技术伙伴协助完成。

### 第一步：写清楚自己的工作

| 你需要说清楚 | 以经营日报为例 |
|---|---|
| 想得到什么结果 | 一份昨天的经营日报 |
| 用哪些资料 | 指定业务系统中昨天完整的数据 |
| 哪些事实必须核对 | 日期、覆盖范围、金额与合计 |
| 哪些动作可以执行 | 先生成供我检查；发送需按既有授权 |
| 怎样证明完成 | 文件能读、数字可核对；如要求发送，需相应回执 |

这些要求由经营者决定，不能让模型凭空替你补齐。

### 第二步：让自己的 AI 先评估怎么接

在把项目文档交给 AI 后，可以这样说：

> 请根据我提供的 Agent + JEV Harness 文档，帮我评估能否用于每日经营日报。先说明当前 AI 是否支持相关工具、缺少哪些条件，再把这项工作的目标、资料和验收标准整理清楚。请区分普通程序能完成的检查，以及值得使用 JEV 的判断；给我一个小范围试点方案。外部调用只使用合成或经我确认可外发的摘要，安装、发送和业务系统修改按现有授权处理。

阅读文档或复制这段话，并不会自动完成安装。不同 AI 产品支持的工具和配置方式不同，需要在实际环境确认。

### 第三步：看懂一个完整示例

以下是**教学示意，不是真实企业效果报告**：

| 阶段 | 发生什么 |
|---|---|
| 任务要求 | 生成日报，并在获准后发送 |
| 实际证据 | 已读取生成的文件；没有发送回执 |
| 待检查声明 | “日报已生成并送达” |
| 检查提示 | “已生成”有依据；“已送达”缺证据 |
| 下一步 | Agent 查询发送状态，或清楚交代“已生成，发送情况待核验” |

其中，“回执是否存在”可以由程序直接检查。JEV 可补充判断较复杂的声明与证据含义是否匹配；不应把每一项检查都交给模型。

仓库中的离线演示使用预设响应，帮助你理解这个流程；真实模型调用另有明确标记。

### 第四步：用小试点判断价值

先保留原有处理方式，让新增检查给建议。由负责人核对：它发现了什么遗漏？误拦了哪些正常结果？你少介入了几次？增加了多少时间和费用？

如果没有收益，就缩小或停用这一环节；如果确实有价值，再扩大到相似工作。

## 可以从哪些工作开始？

| 工作 | 可能有用的小判断 | 当前状态 |
|---|---|---|
| 日报、研究报告、项目交付 | 完成声明是否有相应证据 | 通用接口已实现；有合成日报示例 |
| 客服工单整理 | 诉求属于哪一类，是否表达明确请求 | 后续设计，业务功能未实现 |
| 销售线索整理 | 是否明确表达采购需求、数量或时间 | 后续设计，业务功能未实现 |

开始时优先选结果容易核对、错误可以纠正的工作。

## 你需要准备什么？

- 一件具体工作和一位能验收结果的负责人。
- 一个支持所需工具的 Agent，或能够协助接入的技术伙伴。
- 合成样例或允许用于试点的脱敏资料。
- 真实调用时，自己的 TypeSafe 凭据与可接受的调用费用。

开源代码采用 MIT 许可；第三方模型服务不包含在免费源码里。不要把密钥、客户信息或私有账本提交到 GitHub。

## 目前做到了什么？

已实现开工分流、交付证据摘要复核，以及供技术伙伴使用的 MCP / 命令行入口。已有 17 项核心测试和两个真实合成调用的验证记录。

这些证明初版能够运行，不证明能提高所有企业任务的准确率，也不证明兼容所有 AI 产品。目前没有长期企业效果评估，没有自动接通你的业务系统。

## 下载代码并运行演示

需要 Python 3.11+。在终端中运行：

```bash
git clone https://github.com/Randy0609/agent-jev-harness.git
cd agent-jev-harness
python3 demo.py
python3 -m unittest -v
```

上述演示使用预设响应，不需要密钥，也不调用外部模型。真实接入需要独立安装依赖、配置自己的 TypeSafe 凭据，详见接入指南。
