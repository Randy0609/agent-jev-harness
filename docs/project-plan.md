# Agent + JEV Harness：GitHub 方案初稿

本文保留项目定位、代码交付要求与阅读验收方案。当前首页见仓库 README；这里的读者试读和后续演示计划不代表已完成。

**发布要求：GitHub 仓库必须直接包含 JEV Harness 的完整实现源码、依赖、测试、可运行示例和开源许可。说明文档与代码一起发布，读者可以下载、检查、运行和修改。**

## 一、项目对谁说话

第一读者是企业的经营者：已经在用或准备使用 AI 做工作，却还要反复追问、核对和收尾的创业者、老板。

首页应该使他先看懂三个问题：为什么需要？它是什么、为什么这样设计？自己怎么用？技术伙伴随后通过独立接入文档完成配置。

项目名保留 Agent + JEV Harness，中文副标题建议使用：

> 给你的 AI 助手一套可检查的工作流程。

对经营者的价值假设：帮助发现任务理解和交付中的缺口，减少需要老板反复核对的环节。只有通过真实任务对照后，才能把假设写成效果结论。



### 代码是正式交付的一部分

发布仓库沿用当前已实现的目录，避免文档写了不存在的功能：

```text
agent-jev-harness/
├── README.md                  # 给经营者的三个问题与试用入口
├── core.py                    # JEV 请求、输出校验、分流、复核、额度与审计
├── server.py                  # MCP 工具和 JSON 命令行入口
├── demo.py                    # 无需密钥的离线预设响应演示
├── test_core.py               # 核心行为与失败分支测试
├── verify_mcp.py              # MCP 验证；显式 --live 才进行真实合成调用
├── requirements.txt           # 直接依赖
├── requirements.lock          # 已验证环境的依赖版本记录
├── examples/                  # 合成任务与证据输入
├── skills/agent-jev-harness/   # 给 Agent 使用的技能指引
├── docs/                      # 经营者说明、接入、试点和验证记录
├── .github/workflows/         # 离线 CI 配置
├── .gitignore                 # 排除密钥、运行数据与本地环境
├── CONTRIBUTING.md
├── SECURITY.md
└── LICENSE                    # 本项目源码与原创文档的 MIT 许可
```

下载仓库后，进入目录即可用 Python 3.11+ 运行 `python3 demo.py` 和 `python3 -m unittest -v`，不需要模型密钥。真实接入另按指南安装依赖、配置自己的 TypeSafe 凭据，并在目标 Agent 内验证。

开源范围为我们编写的 Harness 实现、示例、测试、Agent 指引与原创文档。JEV 模型权重及 TypeSafe 在线服务不属于本仓库开源内容，真实调用仍受供应商服务条款和计费规则约束。

### 发布验收分为代码与阅读两部分

代码发布需要核对：远端仓库实际存在上述源码；源码内容与审定版本一致；干净下载后离线示例和测试可运行；依赖与接入说明齐全；没有包含凭据或业务私有数据。创建了 GitHub 页面或上传了压缩包，都不能替代这些检查。

对应代码随本仓库公开。运行与接口检查见验证记录，远端 CI 见仓库 Actions。

以下为建议的信息结构，现有文档可沿用；演示视频属于待制作材料：

这三项尚未经过真实读者试读。可邀请一位目标读者走完整个阅读与试点准备过程，记录卡住的位置后再调整首页。
