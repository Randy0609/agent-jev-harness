# 中小企业试点：把三个问题落到一张任务卡

这张卡首先供企业经营者（创业者、老板）使用。你可以先用自己的话填写业务问题，再让 Agent 或技术伙伴帮助拆分判断、设计检查和完成接入。

先填写业务问题，再决定是否需要 JEV。下面是待采用的模板与合成设计示例，不代表已经接入企业系统。

## 可复制的任务卡

```text

   为什么普通代码 / 现有 Agent 还不够：
   用 JEV 值得验证的假设：

2. Harness 管什么？
   输入来源与时间范围：

   允许的漏报、误报、成本和介入次数：
   停用或退回原流程的条件：
```

## 示例 A：经营日报交付（推荐首个教学场景）

**为什么需要：** AI 经常把“文件生成”与“业务交付完成”合并描述，经营者还要逐项追问。

**Harness 管什么：** 程序先核对报表日期、数据覆盖、汇总与输出文件；Agent 记录真实结果。JEV 仅检查声明和证据摘要是否匹配。账务金额与日期不能交给模型猜测。

**怎么用：** 对现有日报 Agent 增加开工分流和交付复核；先不新增自动发送权限。发送若已获授权，由原有工具执行并保存回执；否则应停在“已生成、待授权发送”。

验收分别记录：源数据已核对、文件可读、发送调用成功、目标位置可见。证据缺失写待核验，不能填零或复用旧数据。JEV 指出缺口后，由 Agent 读取原始证据或缩小声明。

本仓库提供通用复核接口和该场景的合成演示，没有接入报表数据、群聊或企业通信系统。

## 示例 B：客服工单分流（后续设计）

**为什么需要：** 留言有各种自然语言表达，关键词规则可能覆盖不足；每条都交给大模型做完整计划也未必必要。

**Harness 管什么：** 明确定义售前、物流、售后、其他/无法判断等候选；将“主题是什么”和“是否明确请求退款”分开提问。程序核对客户与订单标识，不凭昵称、姓名相似或模糊推断强行关联。

**怎么用：** 首先把建议队列写到本地评估结果，人工按原流程处理。对照完成后再讨论自动登记到预定义队列，届时需要幂等键、失败重试上限和实际登记回执。退款和对客承诺仍按原授权规则处理。

当前没有这个业务连接器或执行器；不要把本例当成可直接运行的功能。

## 示例 C：销售线索整理（后续设计）

**为什么需要：** 同事要从文本中反复识别采购意向，主观排序不一致。

**Harness 管什么：** 分别判断是否表达采购诉求、是否明确数量、是否明确时间，保留原始文字证据。未提及的字段标未知，不补造预算、身份或成交概率。

**怎么用：** 先输出供销售负责人查看的建议，记录人工纠正。禁止从“意向较高”推导出“允许自动联系客户”。联系、报价和优惠由负责人及原有授权流程决定。

当前没有线索分类接口和 CRM 写入能力；如要实施，先用任务卡确定目标与验收，再增加独立问题契约。

## 试点决定是否扩大

先看错误案例，再看平均分。既要看少漏掉多少问题，也要看多拦住多少正常工作。记录每个成功结果背后的人工介入、总耗时与费用；失败样例必须计入。

如果规则方案已经足够，保留规则；如果模型提供的价值覆盖不了额外复杂度，停用该环节。项目的成功标准是工作更可控，而不是 JEV 调用次数增长。
