# 评估：增加一个判断环节，是否真的值得

待验证假设：在可用证据摘要足够的情况下，JEV 辅助可能减少 Agent 对完成情况的过度表述。不能由两个调用、离线预设响应或模型自评推导出成本和准确率收益。

## 比较方法

使用同一批任务、相同主模型、相同工具权限和验收定义。保留三组：原有 Agent 流程、只加确定性证据规则、规则加 JEV。大模型基线允许结构化输出。随机化顺序，保留失败与超时，记录模型版本和提示版本。

调整提示和阈值的样例与最终验收样例分离。至少由业务负责人核对“是否真的完成”；有争议的样例标记争议，不强造标准答案。

## 记录表模板

```csv
case_id,split,arm,agent_model,judge_model,human_complete,reported_complete,gap_detected,elapsed_ms,agent_input_tokens,agent_output_tokens,judge_input_tokens,judge_output_tokens,provider_error,human_review_minutes
```

不在仓库提交真实客户案例。合成案例可以公开，实际业务评估记录按本企业要求保存。

## 核心指标

- 错放：人工判定未完成，但系统报告完成的比例。明确分母为所有未完成案例。
- 误拦：人工判定完成，但系统要求补查的比例。明确分母为所有完成案例。
- 完整流程耗时：包含 Agent、JEV、网络失败与人工复核；报告 p50/p95。
- 总成本：主模型、JEV、重试和人工复核的实际成本；缺价格则保留 token 数，标记费用待核验。
- 额外返工和实际收益：按同一口径比较，零分母或缺数据时写“不适用/待核验”。

先用小样本发现故障，再扩大验收样本并报告不确定性。上线标准由业务负责人事先设定，涉及高损失动作仍保留原有审批与人工判断。

当前尚未运行此业务评估，仓库测试只验证实现分支与接口兼容性。
